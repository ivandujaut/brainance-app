# Abrir un PR

## Antes de abrirlo

1. **Rama:** `feat/NNN-nombre`, `fix/…`, `docs/…` o `chore/…`, creada desde la base del PR:
   - `develop`, para la beta web;
   - `whatsapp-os`, para la línea de WhatsApp (ADR 0100).
2. **Chequeos locales:** `npm run lint && npm run typecheck && npm test`. Si tocaste acciones, adaptadores o el esquema, corré también los de integración:

   ```bash
   TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/brainance_test npm test
   ```

   Si tocaste la UI o un flujo con E2E, corré `npm run test:e2e` (ver [`e2e/AGENTS.md`](../../../e2e/AGENTS.md)).
3. **Prompt o modelo:** si cambió alguno, el eval tiene que haber corrido. Usá la skill `correr-eval`.
4. **Revisión:** pasale el diff al subagente `revisor`, o seguí vos [`docs/agentes/revision.md`](../../../docs/agentes/revision.md).
5. **Commits:** a nombre de `Ivan Dujaut <dujautivan@gmail.com>`, con Conventional Commits y **sin atribución a ninguna IA**. Los hooks de git lo controlan. Si uno falla, arreglá la causa; no lo saltees.

## El PR

- **Base:** la línea de la que salió la rama, `develop` o `whatsapp-os`. Si depende de otro PR abierto, igual va contra esa base, nunca contra la rama del otro PR. Nada de `whatsapp-os` va a `develop`: "Reglas del repo" lo frena.
- **Título:** el mismo formato que los commits (`feat: …`).
- **Descripción** con las secciones de [`.github/pull_request_template.md`](../../../.github/pull_request_template.md):
  - **Qué cambia:** en una o dos frases, más una lista si hace falta.
  - **Spec / ADR.**
  - **Cómo se probó:** con lo que corriste de verdad y su resultado.
  - **QA en el preview.**
  - **Checklist.**
- **Sin firma ni pie de atribución.** En las sesiones de Claude Code en la nube, la conexión de GitHub agrega un pie "Generated by Claude Code" que el agente no puede sacar. Avisale al dueño que lo borre al editar la descripción. El workflow "Reglas del repo" queda en rojo hasta que lo haga.

## Después

- Seguí el CI hasta que esté en verde. Si falla, buscá la causa y pusheá el arreglo; no lo dejes en rojo esperando.
- **El merge lo hace el dueño.**
- Cuando lo mergee, prepará el prompt de QA con la skill `prompt-qa`.
